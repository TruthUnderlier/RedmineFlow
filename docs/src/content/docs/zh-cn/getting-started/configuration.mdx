## 交互式设置

<Steps>

1. 启动登录向导：

   ```bash
   rdflow auth login
   ```

2. 提供你的 Redmine 服务器 URL 和身份验证方式（API 密钥或用户名/密码）。

3. 可选：设置默认项目——该项目会在项目范围的命令中自动填充。

4. 向导将配置写入 `~/.redmine-flow.yaml`，之后即可开始使用。

</Steps>

没有终端时（CI、脚本、AI 代理）可跳过向导：`echo "$KEY" | rdflow auth login --server https://redmine.example.com --api-key-file -`。参见 [`auth login`](/zh-cn/commands/auth/#非交互式登录)。

## 多个配置文件

你可以对任意数量的 Redmine 实例进行身份验证。每次执行 `rdflow auth login` 都会创建一个命名配置文件。

<Tabs syncKey="profile-flow">
  <TabItem label="添加">
    ```bash
    rdflow auth login             # 第二个实例
    rdflow auth login --name work # 显式指定名称
    ```
  </TabItem>
  <TabItem label="切换">
    ```bash
    rdflow auth list    # 查看所有配置文件
    rdflow auth switch  # 交互式选择器
    ```
  </TabItem>
  <TabItem label="临时使用">
    ```bash
    rdflow --profile work issues list
    ```
  </TabItem>
  <TabItem label="状态">
    ```bash
    rdflow auth status
    ```
  </TabItem>
</Tabs>

## 配置文件

<FileTree>
- ~/
  - **.redmine-flow.yaml** 活跃配置文件及所有配置数据
  - .local/bin/
    - rdflow 二进制文件（安装脚本目标路径）
</FileTree>

```yaml title="~/.redmine-flow.yaml"
active_profile: work
profiles:
  work:
    server: https://redmine.work.com
    auth_method: apikey
    api_key: your-api-key
    default_project: myproject
    output_format: table
  personal:
    server: https://redmine.personal.com
    auth_method: apikey
    api_key: another-key
    output_format: json
```

<Aside type="caution" title="磁盘上的密钥">
  配置文件以明文形式存储 API 密钥。请将其权限设置为 `0600`，并避免纳入 dotfile 仓库。在 CI 环境中请使用环境变量。
</Aside>

## 系统密钥环（可选）

你可以将 API 密钥（或密码）保存在操作系统的密钥环中，而不是配置文件里。此功能完全需要主动启用，并向后兼容：现有的明文配置文件将继续照常工作。

<Steps>

1. 在登录时启用。当检测到终端上有可用的密钥环后端时，向导会询问是否使用密钥环。对于脚本化登录，请使用以下标志：

   ```bash
   rdflow auth login --keyring
   ```

2. 该配置文件会记录 `credential_store: keyring`，密钥被写入密钥环而非文件。下次运行时会自动从密钥环读取该密钥。

</Steps>

对于已使用密钥环的配置文件，再次登录时默认继续使用密钥环，绝不会静默回退到明文文件。如需将配置文件显式切换回明文存储，请传入 `--keyring=false`。

解析顺序为：命令行标志、环境变量、密钥环，最后才是明文文件中的字段。环境变量和标志始终在访问密钥环之前解析。

<Aside type="tip" title="CI 与无头环境">
  在 CI 中请继续使用环境变量（`REDMINE_API_KEY`、`REDMINE_PASSWORD`）。在没有可用密钥环的运行器上，设置 `REDMINE_NO_KEYRING=1` 可彻底禁用所有密钥环读写操作，从而避免因密钥环提示而卡住。
</Aside>

## 环境变量

<Badge text="适用于 CI" variant="success" />
所有配置项均可通过以 `REDMINE_` 为前缀的环境变量覆盖：

```bash
export REDMINE_SERVER=https://redmine.example.com
export REDMINE_API_KEY=your-api-key
export REDMINE_AUTH_METHOD=apikey

# 关闭启动时的更新检查
export REDMINE_NO_UPDATE_CHECK=1

# 拒绝所有修改数据的请求（只读模式）
export REDMINE_READ_ONLY=1

# 彻底禁用可选的系统密钥环
export REDMINE_NO_KEYRING=1
```

参见 [自动更新](/zh-cn/commands/other/#启动时更新检查) 了解更新检查的详细信息。

## 全局标志

标志优先级高于配置文件值和环境变量。

| 标志 | 描述 |
|------|------|
| `-s, --server`  | Redmine 服务器 URL |
| `-k, --api-key` | 用于身份验证的 API 密钥 |
| `--profile`     | 使用指定的身份验证配置文件 |
| `--config`      | 配置文件路径（默认为 `~/.redmine-flow.yaml`） |
| `--no-color`    | 禁用彩色输出 |
| `--read-only`   | 拒绝所有修改服务器数据的请求 |
| `--header`      | 额外的 HTTP 请求头，格式为 `"Name: value"`（可重复） |
| `-v, --verbose` | 启用调试日志 |

## 只读模式

将 CLI 指向生产环境的 Redmine 而无需担心数据被修改。启用后，任何会修改服务器数据的请求都会在发送前被拒绝；所有列表、查看和搜索命令继续正常工作。

可通过三种方式启用（优先级：标志 > 环境变量 > 配置文件）：

```bash
rdflow --read-only issues list   # 单次调用
export REDMINE_READ_ONLY=1        # 整个 shell 会话
```

```yaml title="~/.redmine-flow.yaml"
profiles:
  prod:
    server: https://redmine.example.com
    auth_method: apikey
    api_key: your-api-key
    read_only: true
```

传入 `--read-only=false` 可在单次调用中覆盖环境变量或配置文件中的 `read_only: true`。

<Aside type="note" title="MCP 服务器">
  MCP 服务器有自己的开关：只有传入 `--enable-writes` 时才会注册写入类工具（参见 [AI 代理](/zh-cn/guides/ai-agents/)）。配置文件中的 `read_only: true` 会额外在 HTTP 层阻止写入，即使已传入 `--enable-writes`。
</Aside>

## 自定义 HTTP 请求头

部分服务器位于防火墙或反向代理之后，要求附加请求头，例如类似浏览器的 `User-Agent` 或访问令牌。可在配置文件的 `headers` 下按配置文件添加：

```yaml title="~/.redmine-flow.yaml"
profiles:
  work:
    server: https://redmine.work.com
    auth_method: apikey
    api_key: your-api-key
    headers:
      User-Agent: Mozilla/5.0
      X-Proxy-Token: your-proxy-token
```

单次调用时可传入 `--header`（可重复），它会覆盖配置文件中同名的请求头：

```bash
rdflow --header "User-Agent: Mozilla/5.0" issues list
```

传给 `rdflow auth login` 时，这些请求头会用于连接测试并保存到配置文件中，因此需要它们的服务器在首次登录时即可使用：

```bash
rdflow auth login --header "User-Agent: Mozilla/5.0"
```

再次登录时，只要服务器主机不变，配置文件中的请求头会被保留。若将配置文件指向其他服务器，这些请求头会被丢弃，因为它们可能是属于旧服务器的机密信息。如需删除某个请求头，请直接在配置文件中将其删除。

请求头只会发送到配置的服务器，不会发送到其重定向的其他主机。身份验证请求头始终优先。由 HTTP 客户端自行管理的请求头（`Host`、`Content-Type`、`Content-Length`、`Transfer-Encoding`、`Connection`、`Accept-Encoding`）无法配置，空值也会被拒绝。未配置 `User-Agent` 时，CLI 以 `redmine-cli/<version>` 标识自己。

<Aside type="caution" title="请求头以明文存储">
  请求头始终写入配置文件，即使配置文件的凭据存储在系统密钥环中。如果请求头包含令牌，请像对待其他机密一样保护该文件。
</Aside>

## 自定义 CA 证书

如果你的 Redmine 服务器使用由私有或企业 CA 签发的证书（或自签名证书），请求会报错 `x509: certificate signed by unknown authority`，浏览器打开时地址栏也会显示"不安全"。这时需要先导出服务器的 CA 证书，再在登录时传给 rdflow。

### 从浏览器导出证书

以 Chrome、Chromium 和 Edge 为例：

1. 打开 Redmine 网址（例如 `https://redmine.example.com`），点击地址栏左侧的 **不安全** 标记。
2. 在弹出的面板中点击 **证书详细信息**（或"证书无效"）。
3. 切换到 **详细信息** 标签页。在 **证书层次结构** 中选中**最上面**的一项，即根 CA。如果只有一项，说明服务器使用的是自签名证书，直接选它即可。
4. 点击 **导出**，文件类型选择 **Base64 编码 ASCII，单一证书**（也就是 PEM 格式）。不要选 DER 二进制或 PKCS #7 格式。如果是 Windows 的"证书导出向导"，请选择 **Base64 编码 X.509 (.CER)**。
5. 保存到一个长期不动的位置，例如 `~/certs/company-ca.crt`（Windows 可用 `C:\certs\company-ca.crt`）。不要放在"下载"目录或临时目录：rdflow 每次连接都会读取这个文件，文件被移动或删除后就连不上了。

Firefox：点击地址栏左侧的锁形图标，依次选择 **连接不安全** > **更多信息** > **查看证书**，在打开的页面中切换到最右侧的标签（根 CA），然后在"杂项"的"下载"中点击 **PEM（证书）**。

导出后检查一下格式，第一行应为 `-----BEGIN CERTIFICATE-----`：

```bash
head -1 ~/certs/company-ca.crt
```

没有浏览器的机器（例如通过 SSH 登录的服务器）可以用 `openssl` 直接保存服务器发来的证书：

```bash
mkdir -p ~/certs
openssl s_client -connect redmine.example.com:443 -showcerts </dev/null 2>/dev/null \
  | awk '/BEGIN CERTIFICATE/,/END CERTIFICATE/' > ~/certs/company-ca.crt
```

<Aside type="caution">
  导出的证书会被 rdflow 视为可信。请只在确认连接的是真实服务器时导出（例如在公司内网中）；条件允许的话，最好向 IT 部门直接索取 CA 证书，或与其核对证书指纹。
</Aside>

### 登录时使用证书

```bash
rdflow auth login --ca-cert ~/certs/company-ca.crt
```

该证书用于连接测试，登录成功后以绝对路径写入配置的 `ca_cert`。不传 `--ca-cert` 时不会写入 `ca_cert` 这一行。也可以直接在配置文件中设置：

```yaml title="~/.redmine-flow.yaml"
profiles:
  work:
    server: https://redmine.internal
    auth_method: apikey
    api_key: your-api-key
    ca_cert: /etc/ssl/certs/company-ca.crt      # Linux / macOS
    # ca_cert: 'C:\certs\company-ca.crt'        # Windows（使用单引号，或写成 C:/certs/company-ca.crt）
```

- 文件必须是 PEM 格式（以 `-----BEGIN CERTIFICATE-----` 开头的文本），与扩展名（`.crt`、`.pem`、`.cer`）无关。一个文件可包含多个证书。二进制 DER 证书需先转换：`openssl x509 -inform der -in ca.cer -out ca.crt`，Windows 上可用 `certutil -encode ca.cer ca.crt`。
- 这些证书会在系统根证书之外额外被信任，因此公网服务器仍可正常访问。它们只作用于本 CLI 到 Redmine 服务器的连接，不会修改系统信任库，也不影响其他程序。
- 未设置 `ca_cert` 时，行为与之前一致，仅使用系统根证书。文件不存在、无法读取或不含 PEM 证书时会直接报错，不会被静默忽略。
- 在配置文件中手动填写时请使用绝对路径：相对路径按当前工作目录解析，且不展开 `~`。`--ca-cert` 会自动转换为绝对路径。
- 再次执行 `rdflow auth login` 且不传 `--ca-cert` 时会保留已有的 `ca_cert`；传 `--ca-cert ""` 会将其删除。

## 查看当前配置

```bash
rdflow config
```

输出活跃配置文件、服务器、身份验证方式、默认项目、输出格式、只读状态以及已配置请求头的名称（不显示值）。
